If your timer data is missing,
preserve what remains.

Missing tasks or history do not always mean the same thing. Check what you are viewing, avoid replacing files, and contact support before trying a manual restoration.

Preserve the original files before attempting recovery. Show Recovery Files helps locate retained material when a recognized recovery condition exists. Recovery is not guaranteed.

Start with these checks.

  1. Check the context before changing it

    Note the app version, the selected task set, and whether you are using the main XTimers interface or Classic. Classic has a separate local workspace. Note whether you are signed in and which account is displayed; do not sign out or delete an account as a recovery experiment.

    If the problem is a report, also check its task selection and date range. A filtered report can omit data that is still present.

  2. Keep existing files and backups

    Avoid resetting the workspace, deleting app data or using a cleanup tool. Do not copy an old profile over the live app’s files. Preserve any existing Mac backup and note when you last saw the missing tasks.

    If the app cannot open, contact support with the version and the error you see. You do not need to reinstall or repeatedly relaunch it before asking for help.

  3. Locate retained recovery files

    Check for Show Recovery Files as described below. Preserve your existing backups and contact support before moving or replacing files.

Data recovery

What “Show Recovery Files” does.

Open Settings, select About, and look for Show Recovery Files. The button appears only when XTimers detects a recognized recovery condition. Clicking it reveals the relevant retained files or folders in Finder.

It does not restore, merge or upload the files. Keep them in place. Make a separate copy before any repair, and ask support which material is relevant before moving or replacing anything.

Depending on what the app found, Finder may select:

  • LegacyAttic: retained data from an older app layout, when a recovery marker points to it.
  • LegacyRecovery notices or a conflicting-data folder: information and material preserved when the app could not safely combine or open data.
  • An unreadable current profile and UpgradeBackups, when available: the preserved original and any version snapshots relevant to that recovery condition.

If the button is absent, that does not establish that all data is intact, or that no backup exists. The control is conditional, not a general backup browser. Contact support if the workspace is still wrong.

Data recovery

What the protections can—and cannot—preserve.

Older app data

XTimers attempts to import compatible legacy profiles only into an empty, uninitialized modern data folder. It preserves an existing modern workspace and retains older material for recovery rather than treating old data as permission to replace current work.

Successful recovery depends on the original files still being present and readable. These protections cannot recreate files already deleted by an earlier upgrade, cleanup or manual removal.

Upgrade snapshots

When the app version changes, XTimers makes a best-effort copy of top-level JSON files from its data folder into UpgradeBackups. It is designed to retain three versioned snapshot folders.

  • This is not a continuous backup, and it is not a complete copy of the app’s data.
  • Nested folders, media and other files outside those top-level JSON files are not covered by this snapshot operation.
  • A snapshot may be absent or incomplete if copying fails or no eligible files existed. Older snapshot folders are pruned.
  • A retained snapshot is not proof that every task, session or attachment can be restored.

Keep your usual Mac backup current before upgrading. A task template, an exported report and account synchronization serve different purposes; none should be treated as a guaranteed complete recovery copy.

Help support identify the right next step.

Email admin@xintechllc.com with:

  • Your macOS and XTimers versions, and whether you use the main interface or Classic.
  • What is missing: named tasks, a task set, an archive, readings or report history.
  • When you last saw it, and whether the change followed an upgrade, account change or other action.
  • Whether Show Recovery Files is visible, and the folder names it reveals if you already used it.
  • Whether you have a Mac backup from before the problem.

Do not send passwords, security codes, session tokens or recovery credentials. Retained app-data files can contain private information; describe what you have first, and let support explain what is needed.
